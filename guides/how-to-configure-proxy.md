# 指纹浏览器怎么配置代理？参数填写、连接检测与常见问题

代理决定浏览器访问网站时使用哪个网络出口。给环境配置代理前，先准备服务商提供的连接信息，再在对应环境里保存和检测。环境名称可以包含客户或项目名称，便于以后找到正确的窗口。

## 先准备哪些参数？

| 参数 | 填写内容 |
|---|---|
| 协议 | 服务商提供的 HTTP、HTTPS 或 SOCKS5 等类型 |
| 主机 | 代理服务器域名或 IP |
| 端口 | 对应协议使用的端口号 |
| 用户名与密码 | 账号密码认证的代理凭据 |
| 白名单 | 使用 IP 白名单认证时，服务商允许连接的本机出口 |

协议和端口需要配套。代理端口通常与网站的 80、443 端口没有直接对应关系，应按服务商给出的连接参数填写。

静态代理适合需要长期复用同一出口的环境；轮换代理则要关注更换周期和会话保持方式。客户端保存了同一个代理地址，也可能因为服务端轮换而获得不同出口。

## 把代理绑定到一个环境

以支持独立代理配置的客户端为例，先新建或编辑环境，进入代理配置区域，选择协议并填入主机、端口及认证信息。比特浏览器可以在环境设置中检测代理连接，再保存到对应环境。

语言、时区和地理位置按工作需要配置。使用客户端的“根据 IP”之类选项时，保存后在实际窗口中核对结果。经常切换任务时，保留环境与代理的对应关系，避免临时把不同项目共用到同一个工作配置。

## 检测连接后，还要在窗口里看什么？

1. 保存环境并启动浏览器。
2. 打开 [IP 检查页](https://browserleaks.com/ip)，核对实际出口。
3. 打开 [WebRTC 检查页](https://browserleaks.com/webrtc)，查看是否出现其他公网出口。
4. 访问需要使用的网站，确认页面能够正常加载，再登录对应账号。

检测按钮通常确认代理能否连接；在窗口里打开检测页，可以进一步确认浏览器这次请求实际走了哪条网络路径。具体字段含义见[指纹检测指南](how-to-check-browser-fingerprints.md)。

## 连接失败时，从哪里排查？

| 表现 | 先检查哪里 |
|---|---|
| 提示认证失败或 407 | 用户名、密码、套餐状态与白名单 |
| 连接超时 | 主机和端口、网络可达性、协议是否填错 |
| 检测成功，但网站打不开 | 换一个普通网页测试；再检查 DNS、目标网站连接与代理地区 |
| 出口 IP 与预期不同 | 是否启动了正确环境、代理是否保存、服务端是否轮换 |
| 运行一段时间后失效 | 代理到期、流量用尽、会话时长与白名单变化 |

修改代理后先保存，再关闭并重开对应环境。若浏览器仍保留旧连接，先处理连接状态，再判断网站端的问题。

## 批量配置和环境迁移

有多个代理时，按客户端要求的字段顺序整理导入内容，让每条代理对应到正确环境。先选一个环境检查成功，再继续应用到其他环境；不要把含密码的原始代理清单提交到公开仓库。

迁移电脑或工具时，把环境名称、代理和需要保留的 Cookie 一起对应好。复制环境资料后，在新环境重新检查 IP 和登录状态，再交给日常操作。产品选择可参考[比特与 ixBrowser](../comparisons/bitbrowser-vs-ixbrowser.md)，团队交接可看[比特与 AdsPower](../comparisons/bitbrowser-vs-adspower.md)。
